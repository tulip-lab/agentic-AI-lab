# L1：识别隐私泄露、数据泄密和差分隐私边界

## 1. Overview and Learning Goals

完成后，你应能用合成案例区分统计推断与原始记录越权取得，说明差分隐私适用的发布环节，并写出两项需人工核查的问题。无需账号或编程。

## 2. Setup and Background

阅读[共享案例 v3](../../../../Data/case-packs/data-privacy-ai-security/v3/README.md)和本实验的 `data/synthetic-class.json`。编号 SYN-01 至 SYN-06 全是虚构的，`risk_flag` 仅是二元教学变量，不代表真实学生属性。可运行 `python3 run_lab.py risk`，也可根据三人小组的记录手算。

## 3. Core Concepts

A 组的三个标志为 1、0、1。若同时公开“A 组三人的标志总数”与“排除 SYN-03 后两人的总数”，两项精确结果相减就能推断 SYN-03 的标志。这是发布统计时的推断型**隐私泄露**。若外部服务获得全部原始记录，则是权限和外发控制失效所造成的**数据泄密**。差分隐私主要约束统计发布中的单人影响，不能补救已经泄出的原始记录。

## 4. Guided Implementation

先记录 A 组总数与排除 SYN-03 的总数，再计算差值。对照 `risk` 的输出，解释为何即使不出现真实姓名，重叠的精确结果仍可能暴露信息。接着比较 `safe_export` 和 `misconfigured_export`：程序只判断配置是否会让外部角色看到原始数据，不执行导出。

## 5. Testing and Analysis

正常情形：两项重叠查询给出可推断的差值。边缘情形：小组人数很少或发布多张相互重叠的表格，推断风险更值得审查。失败情形：把“给统计结果加噪声”写成“可以随意外发原始记录”，应退回修改。请解释为什么数据最小化与访问限制仍然需要。

## 6. Student Tasks

| 任务 | 目的 | 提交证据 |
| --- | --- | --- |
| 1. 计算重叠查询差值 | 识别推断泄露 | 两个总数、差值与解释 |
| 2. 比较权限配置 | 区分泄露与泄密 | 两种配置的风险判断 |
| 3. 写发布前核查表 | 连接概念与实践 | 发布粒度、查询组合、原始记录访问各一项 |

## 7. Submission and Reflection

提交手算或运行记录、风险分类表与核查理由。检查是否只用了合成资料，并写出差分隐私不能处理的一个问题。若计算结果不一致，先确认选择的是同一 A 组和同一排除对象；若权限判断相反，核对外部角色与导出配置。思考：只删去姓名，为什么不一定足以阻止推断？
